# 管理员后台 - 需求对齐文档

## 原始需求

在现有 VitePress 静态文档站点基础上，构建管理员后台，支持文档的增删改查管理。

## 需求理解

### 1. 现有项目特性

| 维度 | 现状 |
|------|------|
| 项目类型 | VitePress 静态文档站点 |
| 前端框架 | Vue 3 + VitePress 主题 |
| 部署方式 | Docker 单容器（Nginx Alpine） |
| 数据存储 | 无数据库，.md 文件即数据 |
| 构建方式 | `npm run docs:build` → 静态 HTML |
| 运行环境 | Nginx 提供静态文件 + `/api/chat` 反向代理 |
| 技术栈 | Node.js (构建) + Nginx (运行) + Shell (部署) |

### 2. 边界确认

**在范围内：**
- Web 管理后台界面（`/admin` 路由）
- 管理员密码认证
- Markdown 文档 CRUD（创建、查看、编辑、删除）
- 侧边栏菜单可视化管理
- 图片上传管理
- 一键重新构建部署
- 编辑历史/版本记录

**不在范围内：**
- 多用户/角色权限系统
- 对外 API 接口
- 数据库迁移（保持文件即数据的模式）
- 语雀平台同步
- 评论/协作功能

### 3. 技术决策

| 决策点 | 方案 | 理由 |
|--------|------|------|
| 后端框架 | Express.js (Node.js) | 与项目已有技术栈一致，无额外运行时依赖 |
| 认证方案 | 简单密码 + Session Cookie | 管理员单人使用，无需复杂 JWT |
| 编辑器 | 字节跳动 ByteMD (Markdown) | 轻量，支持 Vue/React，分栏预览 |
| 数据持久化 | 文件系统 (.md 文件) | 保持现有架构，无需引入数据库 |
| 版本历史 | Git 提交记录 | 利用现有 Git 仓库，不重复造轮子 |
| 部署集成 | 同一 Docker 容器内，Nginx 反向代理到 Express | 不增加容器复杂度 |
| 构建触发 | 子进程执行 `npm run docs:build` | 复用现有构建流程 |

### 4. 架构方案

```
请求流:
  浏览器                        Nginx (80)                  Express (3001)
  ──────>  /admin/*         ────────>  proxy_pass ────────>  Admin API
  ──────>  /api/admin/*     ────────>  proxy_pass ────────>  Admin API  
  ──────>  /api/chat        ────────>  proxy_pass ────────>  DeepSeek
  ──────>  /*               ────────>  静态文件服务 (dist/)
```

### 5. 疑问澄清

| 问题 | 决策 |
|------|------|
| 管理员密码如何配置？ | `.env` 文件中 `ADMIN_PASSWORD=xxx`，Docker 构建时注入 |
| 是否需要草稿/发布状态？ | 简化：编辑即生效，保存即发布（与语雀逻辑一致） |
| 图片上传大小限制？ | 5MB，仅支持 png/jpg/gif/svg/webp |
| 侧边栏管理粒度？ | 支持增删改一级/二级菜单项，拖拽排序为 V2 功能 |
| 版本历史保留多少？ | 依赖 Git，不做限制 |

## 验收标准

1. 访问 `/admin` 路由，显示登录页，输入正确密码后进入管理后台
2. 文档列表页：显示所有文档标题、分类、更新时间，支持搜索和筛选
3. 新建文档：选择目录（merchant/supplier），填写标题，进入 Markdown 编辑器
4. Markdown 编辑器：左编辑右预览，支持工具栏（加粗/标题/表格/代码块/图片）
5. 编辑文档：加载已有内容，修改后保存，自动更新文件
6. 删除文档：确认对话框，删除 .md 文件，自动更新 sidebar.js
7. 侧边栏管理：可视化菜单树，支持增删改节点、修改链接
8. 图片上传：拖拽/粘贴上传，自动存入 docs/public/images/，返回引用路径
9. 一键构建：点击按钮触发 `npm run docs:build`，显示构建进度，完成后页面可用
10. 退出登录：清除 Session，返回登录页
